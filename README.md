# YOLO + 大模型二次过滤识别系统

当前项目采用 **YOLO 一级检测 + 大模型二级过滤识别** 的技术方案：  
先通过 YOLO 快速定位候选目标，再将候选区域、原图上下文和业务 Prompt 送入大模型进行二次过滤与语义复核，最终输出更准确、更可解释的识别结果。

---

## 当前方案

当前识别流程为：

1. **YOLO 初筛**：快速检测图片或视频中的候选目标，输出检测框、类别和置信度。
2. **大模型二次过滤**：对 YOLO 输出的候选目标进行语义级判断，过滤误报、修正类别、补充属性。
3. **结果融合输出**：结合 YOLO 置信度、大模型判断结果和业务规则，输出最终识别结果。

该方案兼顾了 YOLO 的实时性与大模型的语义理解能力，适合工业质检、安防监控、内容审核、交通识别、零售分析等场景。

---

## 技术架构

整体架构如下：

1. **输入层**
   - 图片、视频流、摄像头、批量文件
   - 支持本地文件、RTSP、HTTP 接口等输入方式

2. **一级检测层：YOLO**
   - 使用 YOLO 系列模型进行目标检测
   - 输出候选框、类别、置信度
   - 负责高召回初筛，尽量不漏掉潜在目标

3. **候选处理层**
   - 裁剪 YOLO 检测到的目标区域
   - 保留原图上下文、检测框坐标、YOLO 类别和置信度
   - 构造大模型 Prompt，例如：
     - 该目标是否属于某类别？
     - 是否存在误报？
     - 是否需要修正类别？
     - 是否满足业务规则？

4. **二级大模型过滤层**
   - 使用多模态大模型 / VLM / LLM 进行二次识别
   - 判断候选目标是否真实有效
   - 修正 YOLO 误判类别
   - 输出过滤结果、置信度、判断理由
   - 可结合规则引擎、知识库、业务策略

5. **融合决策层**
   - 综合 YOLO 结果与大模型结果
   - 支持阈值过滤、投票机制、优先级规则
   - 输出最终类别、置信度、检测框、解释信息

6. **输出层**
   - 结构化 JSON
   - 告警推送
   - 数据库存储
   - API 接口
   - 可视化展示

7. **工程支撑层**
   - FastAPI / Flask 服务
   - Redis / Kafka 消息队列
   - Docker 部署
   - GPU 推理
   - 日志、监控、性能统计

## 优势

- **速度与精度平衡**：YOLO 负责快速初筛，大模型只处理候选目标，避免全量调用大模型。
- **显著降低误报**：通过大模型语义理解进行二次确认，减少传统 YOLO 误检。
- **成本可控**：仅对候选区域调用大模型，降低 Token 消耗和推理成本。
- **可解释性强**：大模型可输出判断理由，便于调试、审计和业务信任。
- **灵活可扩展**：通过修改 Prompt、规则或模型，即可适配新类别和新场景。
- **易于集成**：兼容现有 YOLO 检测流程，可逐步替换或增强原有系统。
- **可持续优化**：识别结果可回流为训练数据，形成数据闭环。

## 后期迭代

- **多模态融合**：结合图像、视频时序、文本、音频等多模态信息。
- **模型轻量化**：通过蒸馏、量化、剪枝，将大模型能力下沉到边缘设备。
- **主动学习**：自动挖掘难例、低置信样本，持续优化 YOLO 和大模型策略。
- **自动 Prompt 优化**：根据业务反馈自动调整提示词和过滤规则。
- **多模型路由**：根据场景复杂度动态选择小模型、大模型或规则引擎。
- **视频时序过滤**：利用多帧信息降低单帧误报，提升视频识别稳定性。
- **平台化能力**：增加任务管理、数据标注、模型管理、报表统计和告警联动。
- **评估体系完善**：建立准确率、召回率、误报率、延迟、成本等综合指标。
- **边缘部署**：支持 Jetson、瑞芯微、昇腾等边缘设备部署。
